# Zetl 1.0.0 RC 3.1

A fix-up of RC 3, plus start at login. Replace both `Zetl.exe` and
`Kastn.exe` (or the AppImage); your notes and settings carry over.

**Windows:** download `Zetl-v1.0.0-rc.3.1-win-x64.zip`, extract it, and run
`Zetl.exe`. It's not yet code-signed, so Windows may show a SmartScreen warning:
choose **More info → Run anyway**.

**Linux:** download `Zetl-v1.0.0-rc.3.1-linux-x86_64.AppImage`, give Zetl
keyboard access once ([Linux setup](https://github.com/vecst/zetl-kastn/blob/release-candidate/docs/linux-setup.md)),
make the AppImage executable, and run it (`--kastn` opens Kastn).

## New

- **Start at login.** A checkbox at the top of Zetl's Settings, on Windows and
  Linux. It uses the system's own startup list, so turning Zetl off in Task
  Manager's Startup apps (or your desktop's autostart settings) shows here too.
  On Linux it starts the AppImage, and finds it again if you move the file.
- **Copied inline pictures.** A copied `data:image/...` address (what "Copy
  image address" gives for an inline picture) is saved as a picture, without
  going online.
- **The Board remembers where you were.** With nothing active in a lane, its
  Board reopens on the project you last had open there.

## Fixed

- **Popup transparency on Windows.** Popup opacity below 100% drew over black
  in RC 3; the desktop shows through again.
- **Holding `Ctrl+B` while editing in Kastn** could leave the Board showing the
  slip's old text and then save it over what you had just typed. The Board now
  picks up Kastn's save.
- **Kastn used CPU while idle.** A hidden "connecting" animation kept Kastn
  drawing all day (about a fifth of a CPU core).
- **Kastn's conflict comparison** ("This slip changed in Zetl while you were
  editing") no longer slides under the status bar in a small window.
- **The Board opened on last week's Journal** after the week rolled over (held
  `Ctrl+B` or `Ctrl+Shift+B`). It now opens on this week's Journal, creating it
  if needed and keeping the lane active, just as a capture does.
- **Popups take the keyboard on GNOME.** The Board opened without keyboard
  focus (Esc did nothing until you clicked it), and with the tour open the
  tour kept the Board's keys.
- **When shortcuts are off, Zetl says why.** Missing keyboard access now
  shows a dialog with an OK button instead of a toast the tour could hide. On
  Linux it names the fix: join the `input` group, restart to finish setup, or
  install the udev rule. The tour skips hold practice while shortcuts are off
  instead of waiting for holds that can't happen.
- **Log settings.** Log retention and lines per day in Settings now take
  effect, and a changed flush interval applies from startup.
- **Linux: capture on GNOME and X11 sessions.** Where the desktop has no
  clipboard-manager protocol, Zetl now uses X11's clipboard, which GNOME keeps
  in step with its own. Checked on GNOME 50 (Ubuntu 26.04): captures, writing,
  large copies, staged pastes, and restoring your clipboard after Replay.
- **Linux: older wlroots desktops.** Zetl now also speaks wlroots' older
  clipboard protocol, so capture works on Sway, labwc, Wayfire, and desktops
  built on them that don't have the newer one.
- **Linux:** Zetl no longer tries to take other programs' virtual keyboards
  (KDE Connect remote input, ydotool, input remappers), and a second Zetl or
  Kastn can no longer start beside the first.

## Linux limits

Linux support is new and has been tested on one desktop. Know these before
relying on it:

- **Tested on KDE Plasma 6 (Wayland), x86_64 only.** Other desktops may work
  but haven't been checked.
- **How Zetl reaches the clipboard depends on the desktop.** KDE Plasma 6 and
  wlroots desktops (Sway, labwc, Wayfire) offer a clipboard-manager protocol
  (`ext-data-control`, or wlroots' older `zwlr-data-control`). Everywhere else
  Zetl uses X11's clipboard: GNOME, which mirrors every copy into Xwayland, and
  X11 sessions. Checked: KDE Plasma 6, Sway, and GNOME 50 on Ubuntu 26.04;
  X11 sessions not yet. On GNOME, whether rich formats (HTML, pictures) come
  across depends on what GNOME passes to X11 apps.
- **Keyboard access is granted to your user,** not just to Zetl: once you
  join the `input` group, any program you run can read your keyboards. The
  [Linux setup](https://github.com/vecst/zetl-kastn/blob/release-candidate/docs/linux-setup.md)
  explains this and how to undo it.
- **Zetl and Kastn run as X11 apps (Xwayland).** On fractional scaling they
  can look too small if the desktop doesn't publish its scale to X11 apps, and
  with monitors at different scales they use one size on all of them. Popup
  placement on several monitors hasn't been verified.
- **Capture origin is partial.** Wayland doesn't reveal which app is focused,
  so captures from native Wayland apps record only "a Wayland window".
- **Media and vendor keys** go straight to the desktop and can't have holds.
- **Not yet verified:** suspend and resume, logging out and back in, and a
  compositor restart (whether the keyboard and clipboard come back on their
  own). If your keyboard ever stops responding, hold both Shift keys and press
  `Esc`.

## Changed

- **Kastn reads only what changed.** After the first load of a project, Kastn
  asks Zetl for just the slips that changed instead of the whole project. Older
  copies of Zetl still get the full read.
- **Compose setting wording.** The `Ctrl+Enter` checkbox now says that,
  unchecked, the result only goes on your clipboard for you to paste.
