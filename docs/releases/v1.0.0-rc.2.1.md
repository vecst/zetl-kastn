# Zetl 1.0.0 RC 2.1

A fix-up of RC 2: one crash and several Replay problems found in testing. If
you're on RC 2, replace both `Zetl.exe` and `Kastn.exe`; your notes and
settings carry over.

Download `Zetl-v1.0.0-rc.2.1-win-x64.zip`, extract it, and run `Zetl.exe`. It's
not yet code-signed, so Windows may show a SmartScreen warning: choose **More
info → Run anyway**.

## Fixed

- **Zetl could close unexpectedly during fast, repeated `Ctrl+C`**, most often
  on the desktop. Several parts of Zetl read the clipboard at the same time,
  and one could end up reading memory another app had just freed. Clipboard
  reads now take turns, and the keyboard itself no longer waits on them.
- **Replay could skip an item** when you pasted quickly into some apps
  (Notepad, with an `Enter` typed right after a paste). Zetl assumed a paste
  landed as soon as the keys were sent. It now moves an item to review only
  once the app you're pasting into has actually read it. If the app drops the
  paste, the item stays first in line, Zetl tells you, and your next `Ctrl+V`
  pastes it.
- **Replay put your clipboard back between pastes**, which could race the app
  still reading the paste. Your clipboard now comes back when the queue runs
  out or you turn Replay off. If Replay ends some other way, your next ordinary
  paste brings it back first.
- **Replay couldn't restore your clipboard on some machines.** Some apps mark
  every copy with an empty Windows enterprise-protection tag, and RC 2 treated
  that as protected content. Only copies that actually name an organization are
  treated as protected now.

## Changed

- Replay's queue items no longer fill up Windows clipboard history (`Win+V`).
- `diagnostics.log` now records each Replay paste (when it was sent and when the
  app read it) and what each Zetl undo reversed, which makes Replay problems
  easier to report. It never records what you copied.

Found something? Please
[open an issue](https://github.com/vecst/zetl-kastn/issues) and attach
`%AppData%\Zetl\diagnostics.log`.
